# Orbit: Architectural & UX Vision Report
**Date:** May 22, 2026
**Status:** Strategic Vision & Roadmap Alignment

## Executive Summary

This document captures the comprehensive architectural and UX vision developed through a deep-dive planning session. It addresses the core product philosophy, the shift toward agentic experiences, the realities of local AI on Android, and the integration of breakthrough technologies like 1-bit quantization and Google's A2UI (Agent-to-User Interface).

---

## 1. The Core Philosophy: A Mobile Attention Memory System

Orbit is not a productivity dashboard, a chatbot, or a cloud graveyard. It is a **quiet daybook** that captures the small things you'd otherwise lose and hands them back to you as a narrative of your day.

### Core Principles
- **Intent Before Artifact:** A capture without context is half-captured. The intent (why you saved it) is key.
- **Under-Deliver on Noise:** The app is quiet by default. It doesn't nag you with notifications.
- **Continuations Grow Captures:** In the background, Orbit uses local extraction to figure out what a capture is.
- **Local-First Supremacy:** The app must work offline. Cloud is an augmentation, not a requirement.

---

## 2. The UX & Information Architecture Pivot

To resolve the tension between "being a quiet memory tool" and "being a proactive AI assistant," Orbit will adopt a **3-Pillar Information Architecture**.

### The "Clarify" Capture Affordance
- A lightweight "Clarify" button on the floating capture overlay.
- Tapping it pops a transparent Android Dialog to instantly type context (*"For Mom's birthday"*).
- This catches the highest-signal context (human intent at the exact second of capture) without disrupting flow across other apps.

### Pillar 1: The Diary (Time)
- A pure, chronological daybook of what you saved.
- No "Mark Handled" nagging, no queue pressure.
- Pure memory.

### Pillar 2: The Library (Space & Search)
- The semantic retrieval engine.
- Fuzzy search, filtering by tags/types.
- Where users go to *find* things.

### Pillar 3: Orbit (The Agent & Action)
- The execution layer.
- This tab houses the Active Intent Cleanup Queue, pending Action Drafts, and dedicated Chat Sessions.

## 3. The Agentic Experience & Knowledge Graph

Orbit will stop guessing and start learning. The agent utilizes the Knowledge Graph (KG) to make actions highly contextual.

### Intelligent Disambiguation
- Orbit will never execute an action blindly.
- If you say "draft a reply to that startup event," Orbit maps the request, finds matches, and asks you to pick the right one via horizontal choice carousels.

### The "Curious Agent" (Proactive Profiling)
- Orbit clusters your saves in the background.
- When a high-confidence pattern emerges, it drops a dismissible, inline poll in the Orbit Tab (e.g., *"Are you a founder?"*).
- The answer writes to the KG, permanently upgrading how Orbit understands you.

### Dedicated Chat Sessions & "The Workbench"
- Deep dives on specific topics (e.g., "Brainstorm this term sheet").
- Users can "attach" past envelopes to the chat context.
- Orbit can proactively suggest: *"I noticed you have 4 saved articles about pre-seed term sheets. Should I extract their full text to supplement our brainstorm?"*

## 4. The Generative UI (A2UI) Breakthrough

Orbit will move beyond the "text chatbot" paradigm using Google's newly released **A2UI (Agent-to-User Interface)** open standard.

### What is A2UI?
- A2UI (v0.9) is a framework-agnostic JSON protocol.
- The AI Agent outputs a declarative JSON block describing its *intent* (e.g., "I want to show a calendar booking card with these dates").
- The client application renders this using its own native component libraries.

### Jetpack Compose Integration
- **A2UI-Android** provides a production-ready Jetpack Compose renderer.
- It takes the A2UI JSON payload from an LLM and inflates it into Compose UI at runtime.
- Secure (no arbitrary code execution), performant (optimized with `rememberSaveable`), and accessible (TalkBack support).

### "The Chat IS the App"
- Instead of text, Orbit's LLMs output declarative JSON intents.
- The `A2UI-Android` renderer instantly inflates these into beautiful, native Android UI components matching Orbit's graphite/cream design language.
- Action Drafts, Calendar invites, email drafts, and disambiguation pickers render natively inside the chat stream.

### Clean Separation of Concerns
- The LLM doesn't decide what the UI *looks* like; it only decides what data needs to be shown.
- Our Android app intercepts the A2UI intent and renders it using Orbit's exact visual design language.
- This ensures the Generative UI never looks like a chaotic webpage. It always looks like a native, beautifully crafted Orbit component.

## 5. The 3-Tier Inference Cascade (The Reality of Local AI)

To honor "Local-First Supremacy" without crashing budget 4GB RAM phones, Orbit relies on a three-tier model cascade.

### Original Plan (AICore-Based)
1. **Tier 1: Native AICore (Gemini Nano)** - Instant, OS-level inference for flagship hardware.
2. **Tier 2: The "1-Bit Brain" (Local 8B Model)** - For mid/high-end Androids (>8GB RAM).
3. **Tier 3: The Cloud Gateway** - For low-end phones.

### Refined Plan (BYOM - Bring Your Own Model)
**Decision:** Abandon reliance on Google's restricted AICore service. Ship our own inference engine (LiteRT-LM or MLC LLM) with hardware-tiered model options.

#### The Core Engine Replacement
- Strip out dependency on Google's `AICore` service.
- Compile **MLC LLM** (or **LiteRT-LM**) directly into the Orbit APK via C++/JNI bindings.
- Provides direct access to mobile GPU via Vulkan.
- Guarantees consistent behavior across Samsung, Xiaomi, OnePlus, etc.

#### The "Model Store" Experience (BYOM)
When a user toggles `Local-First Mode` on, Orbit assesses their hardware (Available RAM, GPU) and offers a tiered download screen:

**Option A: The "Speed" Model (Gemma 2 2B)**
- *Download Size:* ~900 MB (INT4)
- *Hardware Req:* 4GB+ Total System RAM
- *Capabilities:* Lightning fast. Perfect for Basic Understanding (extracting dates, prices, intent). Struggles with complex creative writing.

**Option B: The "Intelligence" Model (Bonsai 8B 1-bit)**
- *Download Size:* ~1.15 GB
- *Hardware Req:* 4GB+ Total System RAM (tight, requires background app cleanup)
- *Capabilities:* Desktop-class reasoning. Fully capable of generating complex A2UI JSON structures, drafting deep conversational emails, and semantic RAG over your Knowledge Graph.

**Option C: The Cloud Gateway (Default)**
- *Download Size:* 0 MB
- *Hardware Req:* Any phone (4GB RAM)
- *Capabilities:* Uses Anthropic Haiku/Claude 3.5 via our secure Supabase gateway.

#### Graceful Degradation in the UI
- If a user is running the **Speed Model (Option A)**, Orbit disables the "Ask Orbit" deep-chat feature offline because a 2B model will hallucinate on complex tasks. It only uses the local model for the Action Cleanup Queue.
- If a user is running the **Intelligence Model (Option B)**, the entire A2UI Generative interface unlocks offline.

## 6. The Ivy Inspiration: Key Takeaways

From the analysis of the Ivy AI Tutoring Agent (Natnael Getenew Zeleke):

### 1-Bit Quantization is a Deployment Paradigm Shift
- PrismML Bonsai allows an 8B parameter model to run in just **1.15 GB** using 1-bit quantization.
- This makes flagship-level reasoning possible on budget devices ($80 Samsung A14).
- Changes the math completely for what we thought was possible on mobile.

### Inline Interactive Components
- "The chat IS the classroom. Zero navigation."
- AI renders quizzes, flashcards, study plans as interactive UI widgets directly inside the conversation stream.
- Eliminates context-switching. The user never loses momentum.

### 3-Layer Offline Architecture
1. **Fully Cloud:** Bedrock/Cloud orchestration when internet is perfect.
2. **Fully Local:** 1.15GB quantized model kicks in when internet drops.
3. **The Bridge:** Pre-cached logic. Cloud layer pre-downloads data so local layer has content to work with offline.
- **Economic Insight:** Cloud cost drops to practically zero ($0.0016/student/month). Server only used for orchestration and memory sync.

### Proactive, Multi-Channel Escalation
- Background 5-minute cron job checks state.
- Escalates: *Nudge → Push Notification → Outbound Voice Call.*
- 100% call acceptance in pilot. Forces engagement in a way passive push notifications (5-15% open rate) never will.

## 9. Technical Stack Decisions

### Inference Frameworks
- **Primary:** MLC LLM (Apache TVM) - Best for Vulkan GPU acceleration and broad model support.
- **Alternative:** LiteRT-LM (Google's new standard) - Best for Gemma 2 models and tight Android integration.
- **Abandoned:** Google AICore (Gemini Nano) - Too restricted to flagship hardware.

### Models
- **Speed Tier:** Qwen 2.5 1.5B (INT4) - ~900MB
- **Intelligence Tier:** Phi-3 Mini 3.8B or Llama-3 8B (1-bit) - ~1.2GB-1.8GB
- **Cloud Fallback:** Anthropic Haiku / Claude 3.5 Sonnet via Vercel/Supabase Gateway

### UI Framework
- **Generative UI:** Google A2UI (Agent-to-User Interface) v0.9
- **Renderer:** A2UI-Android (Jetpack Compose)
- **Design Language:** Custom graphite/cream theme (`.specify/memory/design.md`)

## 10. Strategic Advantages

1. **Universal Compatibility:** BYOM approach ensures Orbit works on 90% of Android phones, not just flagships.
2. **Privacy by Design:** Local 1-bit models enable desktop-class reasoning offline, with sensitive data never leaving the device.
3. **Sovereign Architecture:** No dependency on Google's hardware rollout schedule or OS updates.
4. **Magical UX:** A2UI enables "The Chat IS the App" paradigm with native interactive components.
5. **Economic Sustainability:** On-device inference drives cloud costs to near-zero, making the product economically viable at scale.

This vision transforms Orbit from a "smart gallery app" into an **operating system for your attention**.
